# Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the local Node backend with a portable Rust executable and push a verified feature branch.

**Architecture:** Embedded browser assets, async loopback HTTP, typed persistent profiles, external SSH/SCP/tar, embedded Bash templates. Existing Node code is a test oracle only.

**Tech Stack:** Rust, Tokio, Axum, Serde, tempfile, existing vanilla JavaScript frontend.

**Spec:** docs/superpowers/specs/2026-10-25-rust-port-design.md

## Global Constraints

- Bind only 127.0.0.1, default port 4321.
- No local Node requirement for packaged application.
- Preserve existing configuration and API workflows.
- Create a new codex/ branch after implementation and verification, then push it.

## Review Focus

- Existing malformed or legacy configuration must produce useful errors and never erase settings.
- Disconnects/timeouts must stop local subprocess work and release operation locks.
- Removal must never weaken path/symlink/overlap validation.
- Streamed secrets/UTF-8 and upload failures must not leak or leave temporary files.
- An EXE moved away from source must serve all assets and use its own config location.
